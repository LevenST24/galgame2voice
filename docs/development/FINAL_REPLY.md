# 终稿与舞台的衔接

`conversation.js` 是历史记录的写入者，舞台只消费控制器事件。服务端终稿可能补齐
尚未收到的逐句台词与音频结果；显式选择的 `legacy` 模式也只承诺整段文本和音频。
不能仅凭没有逐句事件就把成功回复直接结束到输入框。

控制器在完成前补齐尚未发出的 `line` 与 `line_audio`，按台词索引展示。已经发出的
台词和音频结果不重复发送，避免音频仍在下载时被终稿再次启动。终稿里仍为 pending
的音频转为明确失败，文字与后续推进继续可用。补齐过程仍属于当前轮的 busy 阶段，
不会允许事件监听者提前启动下一请求。

整段回复在本轮演出时作为一条台词，音频切片顺序和重复 URL 的位置均保留。这个
临时台词不加入保存的 `message.lines`，避免把展示索引零冒充服务端历史行身份。
失败与取消不自动启动整段回复播放；已收到的内容仍按原有规则保存供 LOG 查看。
只有日文的回复也是有效内容，不能因缺少中文增量而丢弃。

服务端保存完整或中断的回复前，会在同一写事务内核对原始用户消息仍属于该会话。
会话被删除、清空或以同一 ID 重建后，旧回复不会重新创建会话或写进新会话；流式
请求也不会发送成功的终稿。同步请求报告该轮对话已不可用。保存状态和消息 ID 由
事务的提交后回调记录：即使提交成功后请求立即取消，清理流程也不会重复保存回复
或误删对应的用户消息；事务回滚时不会将回复标记为已保存。

`tests/test_conversation.mjs` 覆盖事件补齐、去重、身份、请求串行和日文保存；
`tests/test_final_reply_browser.py` 将真实 SSE 解析、控制器、舞台和文本框一起运行，
覆盖桌面尺寸、旧格式、仅终稿台词、缺失音频事件及不重复播放。
`tests/test_chat_commit_cancellation.py` 和 `tests/test_chat_session_deletion_race.py`
分别覆盖提交边界的取消、回滚和会话删除、清空、同 ID 重建的竞争。
