# 模型设置的异步保存与草稿

聊天体验通过同一会话写入队列保存。当前页面先应用本次设置，设置窗口保持打开并
显示保存中，直到本机服务确认。失败时在当前编辑器保留草稿和重试按钮，不自动
重发 POST；关闭或切页不会撤回已经发出的写入。关闭时只还原本次提交之后的未保存
预览，已应用的提交值保留。显式保存也会使较早的启动列表同步失效，避免旧快照覆盖
当前修改。
保存状态带有可读通知，出现时滚入设置正文的可见区域，不改变输入焦点。

体验编辑器以会话对象、打开版本和提交快照核对异步结果。成功只关闭仍属于原操作且
没有新增编辑的窗口；新草稿保持打开并说明已保存的范围。关闭、返回首页或重新打开
后，旧成功不关闭新窗口，旧失败通过原会话的提示报告，不写入新编辑器。共享页脚与
独立编辑器均保持保存中状态；同步调用方仍保留原同步返回行为。
`tests/test_experience_settings_save.mjs` 和 `tests/test_unified_settings_browser.py` 使用
延迟和失败的合成接口覆盖上述路径，不读取真实配置。

模型表单与全局配置都有编辑版本。点击保存时捕获当次提交的字段；请求期间继续编辑
会推进版本，成功响应仅确认已提交的快照。当前新草稿保留到下一次主动保存。

`global_settings.js` 用 `dirtyProviderFields` 标记用户实际修改的模型字段。列表刷新可以
更新提供商清单、已启用模型和状态徽标，但跳过这些字段的回填，因此输入内容、光标、
模型下拉框选择及 API Key 显示状态得以保留。显式切换提供商则丢弃原提供商草稿并
填入新选择的配置。恢复默认地址也属于用户编辑。

列表请求使用单调递增的序号，旧响应不发布到较新的状态。保存后的列表刷新还携带
保存开始时的编辑版本，防止当前选择或草稿被旧操作覆盖。模型与全局保存按钮共用
忙碌状态，输入字段继续可编辑；成功、失败后都恢复按钮可用状态。

模型与全局配置经两个 API 保存，不宣称跨接口事务：模型已保存而全局配置失败时，
提示分别说明结果；重试全局保存不会重复提交已经确认且未再修改的模型。

同一页面的全局配置写入、计算方式自动保存与重启 POST 通过 `runSettingsMutation`
在用户操作时预约顺序。页脚保存先捕获模型草稿并启动模型保存，同时预约全局写入，
避免之后的自动保存抢先执行再被旧快照覆盖。重启响应不覆盖请求期间的新计算方式
选择；重启 POST 完成后释放队列，不占用整个模型加载时间。

断连、超时或服务器 5xx 后，非密钥配置只读核对一次已提交字段。含新 Token 的
写入不从脱敏值确认，也不自动重发。无法确认的写入会阻止当前已排队的后续写入
与重启，输入保留；当前批次结束后允许用户重新主动保存。模型请求若已经启动，
即使全局写入被跳过，也等待模型结果后分别报告，避免把部分成功说成全部失败。
这只约束同一页面，不提供跨窗口的版本冲突检测。

`POST /api/providers` 的 `is_active: true` 在同一数据库事务里保存字段并启用模型。
当响应明确确认当前 ID 已启用，前端直接使用该结果，避免第二次启用请求造成误报，
或覆盖另一窗口随后选择的模型。没有确认启用状态时，才调用启用接口。

`provider_recovery.js` 对超时、断连或无法读取的成功响应只进行一次只读核对：
使用 10 秒时限及 `cache: 'no-store'` 读取单个提供商，逐项比较本次提交的非密钥
字段及启用状态；不会自动重发写请求。保存载荷包含新 Key 时不以脱敏值核对，
而是保留输入并明确提示结果未确认。启用响应丢失时，前一次保存已有确认，
因此可以只核对启用状态和非密钥字段。HTTP 拒绝及主动取消保持原错误。

回归用例位于 `tests/test_reasoning_effort_ui.mjs`，`model draft` 分组覆盖保存、启用、
刷新期间编辑，切换提供商、迟到列表、默认地址、忙碌状态和部分成功。测试使用合成
Key 和假 API；真实页面验收应另行确认原生输入事件、光标与按钮交互。
`tests/test_provider_recovery.mjs` 覆盖响应丢失、字段不匹配、脱敏 Key 碰撞、
核对失败、HTTP 拒绝和取消；真实控制器测试还确认已启用时不再发送第二次写请求。
`tests/test_settings_write_order.mjs` 进一步覆盖快速切换计算方式、保存与重启交错、
页脚模型保存期间继续编辑、未确认写入阻断与后续主动恢复、部分成功提示。
