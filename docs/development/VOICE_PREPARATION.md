# 首句语音的模型准备

聊天的文字输出不等待音色切换。语音任务需要一个已经解析且包含两份模型权重的
音色上下文；`TtsService` 给该上下文发放内部不可变 `VoicePreparation` 标记。
HTTP JSON 不能伪造这个类型，服务入口也会清除传入的旧标记后重新解析。

缓存命中直接使用该音色、文件版本和引擎地址对应的音频，不加载权重。缓存未命中
进入引擎互斥锁后，客户端先核对排队时捕获的文件与地址，再检查模型是否匹配。
只有可信上下文可触发准备；需要加载时先执行 `VoiceResourceGuard` 的 RAM/VRAM
预检，并在预检后再次核对地址。加载和当前音频合成都在同一个锁范围内，手动切换
不能插到这两步之间。普通、文件和流式入口共用该边界。

`switch_voice_profile` 是取得锁的公共入口，`_switch_voice_profile_locked` 是已有
锁内加载/回滚流程的抽取。自动准备调用后者，不重复取得同一个 asyncio.Lock。
资源策略从 `VoiceManager` 提取到 `voice_resources.py`，管理器保留原入口与错误
类型的导出，显式切换与自动准备使用同一套阈值、释放与拒绝逻辑。

显存预检优先使用原生命令；原生查询失败时只复用已完成加载的 PyTorch，不为
资源检查冷导入框架，也不等待其他线程尚未完成的导入。框架回退的可用显存和
总显存都读取设备 0，避免线程默认设备不一致。无法取得读数时保留原有未知值
策略，已知内存不足仍拒绝加载；真正启动引擎的完整硬件探测不受此限制。

自动准备只改变当前引擎工作模型，不改变用户保存的全局启用音色，也不建立额外
数据库迁移或配置项。加载失败或被取消时仍保留未确认状态，不发送错误音色的 TTS，
不缓存半成品；下一次完整音色请求可在资源允许时重新加载。

文件版本或端点在排队期间改变，仍拒绝旧请求。部分模型配置不会与引擎现有模型
拼接成自动准备目标；裸参数和匿名预解析保持原来的严格校验。应用之外直接换远端
权重或引擎重启而未通知应用，仍受可观察状态的限制，不宣称远端模型认证。
