# 设置页诊断读取与任务所有权

设置页的引擎状态、缓存统计和完整系统诊断分别更新。引擎已经确认就绪时，不等待目录
扫描或硬件信息才显示在线。所有更新，包括缓存容量、PID 和运行时间，都必须属于当前
刷新；关闭后重新打开、手动刷新或重启后，旧响应不能覆盖新页面。

前端每轮读取共享一个 AbortController。关闭设置、页面进入后台或新刷新替代旧刷新时
取消正在读取的 GET；回到前台立即启动一轮，上一轮不能再创建定时器。隐藏面板收到迟到
的保存回调时，不重新启动状态读取。系统诊断和缓存读取沿用 15 秒时限，引擎状态沿用
10 秒时限，不增加重启或保存 POST 的自动重发。

引擎在线不证明此前丢失响应的重启请求已执行。未确认提示在后续在线刷新中继续保留；
收到新的明确重启响应后才清除，实际计算方式仍以匹配受管进程的启动记录为准。

## 后台工作由谁持有

| 工作 | 所有者 | 读者取消后的行为 |
| --- | --- | --- |
| 引擎连通性探测、单次状态拼装及元数据读取包装任务 | 当前 HTTP 请求 | 断连后取消并收尾，不留下请求自己的异步任务 |
| 同一目录的在途扫描、静态 GPU 清单探测 | 应用内的 `TelemetryJobs`，按事件循环隔离 | 一个读者取消不影响其他读者，共享测量可完成供后续读取复用 |
| 计算方式、当前受管引擎归属和配置 | 各次请求 | 不缓存进共享 GPU 清单，慢探测结束后重新读取 |

`TelemetryJobs` 只保留正在执行的任务。完成或失败后移除并取回异常，下次读取可以重试；
应用退出时先取消这些异步任务，再进入服务和线程池的关闭流程。已进入 OS 的线程操作
不能靠取消 asyncio 等待强制终止，仍由原有执行器关闭流程收尾；不能把“取消等待”写成
“已停止所有磁盘或显卡驱动操作”。

目录结果按规范化绝对路径缓存，统一相对路径和 Windows 常规大小写形式。缓存的十五秒
期限从扫描完成后开始，最多保留 64 个目录结果。静态 GPU 清单沿用六十秒缓存期，也从
完成后计时。并发状态请求复用在途工作，不为每个浏览器刷新重复提交一遍扫描和显卡查询。

状态读取以 `allow_torch_import=False` 查询显卡：原生信息不可用时，不冷导入 PyTorch，
也不等待其他线程尚未完成的框架初始化。已有完整框架结果可以复用；实际引擎启动
继续保留默认的完整探测路径。下一次启动精度的解析接收当前 GPU 采样，不再另测一遍。
原生信息缺失且只能使用硬件默认值时，下一次计算方式和待重启状态返回未知；明确的
环境、数据库、校准缓存和 YAML 配置仍按原优先级解析，状态读取不改写这些配置。

目录统计可能略过无法访问项，仅用于诊断展示，不作为删除音频、备份或恢复数据的依据。
数据目录存在性检查也在线程中执行，避免慢盘元数据访问阻塞事件循环。

请求拥有的任务统一经 `utils/async_tasks.py` 收尾，兼容最低 Python 3.10，
不使用 3.11 才提供的任务取消计数接口。重复取消不会再次中断子任务的清理；收尾后
仍向调用者传递取消。已完成文件的删除也等待收尾，正在执行的 OS 写入继续由原工作
线程的放弃标记清理，不阻塞等待整个写入结束。

## 验证边界

- `tests/test_settings_telemetry.mjs`：关闭、后台隐藏、重新打开、迟到数据、定时器以及引擎卡独立更新。
- `tests/test_telemetry_ownership.py`：目录与 GPU 并发复用、取消隔离、缓存计时与容量、失败重试、数据库元数据不阻塞及应用关闭顺序。
- `tests/test_async_task_cleanup.py`：最低支持运行时、重复取消、失败任务的同组清理和异常回收。
- `tests/test_gpu_status_budget.py`：原生查询失败、框架正在初始化时禁止冷导入，以及复用采样和未知精度语义。
- `tests/test_telemetry_ownership_browser.py`：真实浏览器 GET 被中止，慢诊断期间引擎卡已在线，重新打开后旧数据不能回写；覆盖桌面尺寸。
- `tests/test_engine_status_browser.py`：兼容原有启动、短暂探测故障及重启响应丢失流程，未确认提示不能被周期刷新抹掉。

回归使用临时目录、合成数据和独立浏览器，不以这些检查证明真实 GPU 推理速度。
