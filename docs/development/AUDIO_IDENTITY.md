# 音频缓存与实际合成的一致性

## 请求快照

`TtsService` 先解析音色，再绑定客户端的有效默认值，最后在工作线程中读取文件标识。
`audio_identity.AudioIdentity` 是请求内的不可变快照：GPT 权重、SoVITS 权重、参考音频、
引擎地址。文件标识包含规范化完整路径，以及可读取文件的修改时间、大小、ctime、
设备号和文件号；不读取或哈希整个大型权重文件。

有音色选择条件时，完整参考音频不会跳过模型解析。预解析调用同时提供两个模型字段
即可跳过数据库；匿名完整引用和匿名预解析仍不查数据库。每次服务请求重新读取文件
标识，所以同路径替换也会产生新的缓存键。相对参考路径以安装目录及既有音频路径
解析器为准，不依赖启动器的当前目录。实际请求载荷与缓存使用相同解析顺序。

## 缓存归属

缓存键版本为 3，包含数据库的规范化路径、有效推理参数、引擎地址和文件快照。
这不是数据库 schema 版本升级。已有历史引用的 WAV 不删除，但不会作为新请求的
音频复用。不同路径的同名、同大小和同修改时间参考文件也不能互相命中。

缓存管理器按 `(数据库路径, 缓存目录)` 复用；显式创建其他数据库的缓存不会取代
应用默认缓存。关闭应用时统一排空所有应用持有的管理器；显式注入的管理器仍由
持有它的服务或调用方负责关闭。
`ChatService` 创建默认 TTS 依赖时传入自己的数据库；注入现有服务的调用方负责
选择具有相同数据库归属的实例，不能把另一个数据库的默认服务当作该会话的音色。

`VoiceManager.stream_tts` 统一委托其 `TtsService`，使用同一套身份、缓存与取消逻辑。
移除旧的独立流式缓存与后台写入实现，避免两个入口对文件身份或取消条件各自处理。

普通、文件及流式入口在调度器实际开始执行时再次检查相同身份的缓存，复用排队期间
已经完成的普通或文件合成。流式复查沿用分块读取，TtsService 不重复累计整段缓存音频，不重写已有
文件，也不重复记录缓存未命中。关闭缓存时仍请求引擎；取消分块重播时关闭缓存流并
释放调度任务。此复查不合并两个尚未完成、尚未写入缓存的流式请求。

## 缓存读取与恢复

磁盘流在打开句柄后记录文件身份和大小，分块读取过程中检查意外提前结束。首字节前
失败按缓存未命中处理；已经输出部分音频后失败则抛出 `CachedAudioReadError`，不能
把截断视为成功结束，也不能在半份 WAV 后追加一份重新合成的 WAV。

读取失败仅在内存中标记对应的文件版本，最多保留 256 项，不删除原文件。三个合成
入口都会绕过匹配的出错版本，让后续合成请求重新生成。成功写入或文件版本变化会
解除标记；迟到的旧读取失败不会屏蔽较新的原子写入。原地截短但文件身份未变时，
标记截短后的版本。Windows 比较路径 `stat` 和句柄 `fstat` 时使用共同的文件身份、
大小与修改时间，避免两者 `ctime` 语义不同造成失配。

Windows 缓存替换使用最多五次短重试。未替换成功时保留旧文件与元数据并报告写入
失败，不以旧文件非空作为成功依据；文件合成沿用临时音频回退，返回本次实际生成
的音频。该恢复覆盖服务合成请求；LOG 对已有音频 URL 的重播不会自动触发重新合成。
未覆盖音频的所有格式损坏类型，或通过修改元数据伪装文件版本的情况。

## 浏览器音频副本恢复

`cache.js` 的 `loadAudioBuffer` 协调读取、原生解码与一次只读恢复，单句及流式播放器
共用；LOG 预先下载后传入的 Blob 也进入相同流程。`EncodingError` 表示当前副本未能
解码：先尝试同页面较新的内存副本，再按需以 `cache: no-store` 对同一 URL 补发最多
一次 GET。全部步骤处于原有下载/解码总时限内，取消与迟到结果不触发播放或缓存覆盖。
普通有效缓存命中不发额外请求，也不重写持久缓存。

浏览器持久缓存继续使用 `gal2voice-audio-v1`，新增内部版本头并兼容没有此头的历史
记录。坏副本按键和版本移除，读取和预取有版本所有权检查；同一页面的持久写入与删除
按键串行并合并最新目标，避免较慢的旧写入在清理后重新覆盖有效副本。不同键的录音
保存不会因为其他键忙而被丢弃。内存音频仍限制 50 条，版本状态限制 100 个键。

浏览器空闲清理只限制可识别的生成语音副本（`/audio/` 和 `msg_` 键），不会将
用户录音或归属不明的旧缓存按数量自动删除。录音仍受浏览器存储配额、用户手动清除
站点数据和浏览器自身回收策略影响；聊天 JSON 备份不包含录音 Blob，已被清理的录音
也无法通过这个改动恢复。

录音 Blob、`blob:` 地址和消息缓存键不会被擅自当作网络 URL 请求；恢复不会清空全部
音频缓存，不自动重发合成 POST。服务器音频本身持续损坏时，用户可在 LOG 明确点击
“用当前音色重新生成”。实际浏览器回归使用独立配置、真实 CacheStorage 和原生 AudioContext
播放短合成 WAV；不访问用户录音或真实模型。

`tests/test_audio_cache_recovery.mjs` 覆盖缓存分层、旧格式、预下载 Blob、迟到读写、预取、
较新有效副本、取消、总时限、持续失败、无额外命中写入、并发录音保存与自动清理；
`tests/test_audio_cache_recovery_browser.py` 用真实时间等待原生解码/播放和磁盘缓存，
不以推进虚拟 JS 时钟替代原生异步完成。

## 引擎边界

显卡能力查询复用已加载的 PyTorch；未加载时先查询原生设备清单，只有原生清单都没有
结果才导入框架。状态页不应仅为读取显卡名称触发冷导入或 CUDA 上下文初始化。
`tests/test_gpu_native_probe.py` 覆盖原生路径不导入、已加载设备优先及无原生信息的回退。

### LOG 单句重新生成

重建只使用当前会话明确绑定的音色，按钮提示音色名称；没有绑定时进入“角色与会话”
选择。指定音色已删除或读取失败会提示重新选择，不能借用引擎当前角色。请求只带这句
日文与推理选项，`use_cache=False` 生成独立的 `repair_` 音频，不发送 LLM 请求、不改写
全局启用音色，也不覆盖旧音频文件。生成完成后由用户点击播放，不自动响起。

服务端历史通过 `message_id`、会话和原日文校验归属，生成后在事务内重新核对目标音频
版本，只合并这一句；目标已变化则拒绝覆盖，已删除则不重建记录。聊天时间保持原值，
音频用 `generated_at` 判断七天可播时间。新音频同时记录所用音色 ID 与名称。

`audio_artifacts.py` 统一处理新文件的所有权和修复文件命名。独占创建避免文件名碰撞时
覆盖原音频；磁盘写入失败、部分写入或取消后工作线程迟到完成，均清理这次新建的文件。
取消不等待仍在进行的磁盘写入，写线程关闭句柄后负责回收；Windows 占用导致删除失败
时记录警告，保留原错误，交给后续清理重试。
不使用缓存的合成任务会跟踪自己创建的文件，调度结果交接时取消同样回收；忽略取消后
才结束的客户端不会继续发布音频。共享缓存及缓存失败后的回退结果不按独占任务删除。

`repair_` 加十二位十六进制编号的 WAV 按七天保留，其他临时音频仍遵循用户配置的分钟
保留期。参考音频保护优先于上述期限。空音频、生成后取消以及历史版本冲突仅清理本次
未采用且位于音频根目录的修复文件，不清理共享缓存或旧音频；进入数据库写入后，提交
可能已成功，未确认结果的文件继续保留，避免取消或响应丢失造成历史引用断开。等待历史
事务期间断开的请求会在真正开始更新前重新核对连接。

`tests/test_audio_artifact_lifecycle.py` 用真实文件、写线程屏障和故障注入验证半文件清理、
取消、重名保护与删除范围；单句接口回归同时经过实际后台清理器检查一小时和八天的
文件，验证参考保护及提交后取消不会删除已引用音频。

历史接口和成功提交后的 SSE `done` 提供可信消息 ID。浏览器本地或导入记录没有这个 ID
时只保存本地修复结果，并明确提示；不能从类似 `m_42` 的浏览器 ID 猜测数据库 ID。
关闭 LOG、返回首页或切换播放会取消此操作；请求结果未知时保留原音频，不自动重发 POST。

`tests/test_line_audio_regeneration.py` 使用临时数据库、真实合成服务及 WAV 桩检查缓存旁路、
事务冲突、删除、断连和音色归属；`tests/test_line_audio_recovery.mjs` 覆盖请求与前端操作
所有权；`tests/test_line_audio_recovery_browser.py` 用独立浏览器在桌面尺寸核对真实
按钮命中、取消、无自动播放及原生音频播放结束。这些测试不证明真实 GPU 性能。

普通合成、模拟流式和 HTTP 流式都会在取得共享推理锁后检查文件快照、引擎地址和
客户端已知的当前权重。排队过程中换文件或引擎地址会终止该请求，不向上游发送
合成请求，也不向新身份写入错误音频。网络重试前再次校验。

客户端记录每次成功加载权重时的文件版本。同路径覆盖后，原先加载的版本仍被视为
旧版本；重新选择音色会重新加载变化的权重。由服务端成功解析、同时具备两份权重的
音色上下文会获得内部 `VoicePreparation` 标记；缓存未命中且当前模型不匹配时，
客户端在同一推理锁内经过共享内存/显存预检、加载所选模型，再核验文件和执行合成。
这个过程不改写数据库中的全局启用音色。裸参数、普通 JSON 标记、部分模型配置和
匿名预解析不会授权自动加载。引擎地址切换后，旧地址状态不再视为新地址的状态。
模型加载和回滚请求核对端点 generation；切换地址后到达的旧响应不会发布到新引擎
的状态，也不会继续向新地址执行旧切换的回滚。单独加载权重及设置参考也共用推理锁。
模型加载被取消或回滚失败时，客户端明确保留“状态未确认”标记；裸参数生成仍会
提示重新选择音色。后续完整的已解析音色可以经过资源预检后完整加载，成功才清除
标记；回滚 HTTP 错误不视为成功恢复，低内存时不会因状态未知而绕过保护。

此机制核对的是本应用可观察的状态：外部工具直接更换远端引擎模型而不通知应用、
远端文件不可见、或内容变化却刻意恢复全部元数据，不能靠本地路径与 stat 证明。
这里不声称完成远端模型认证，也不以合成桩测试证明真实 GPU 的音色和性能。

## 回归

`tests/test_audio_cache_identity.py` 使用临时数据库、模型标记文件和生成 WAV，覆盖
三种合成入口、完整引用旁路、预解析、同路径替换、参考路径碰撞、数据库归属、
锁等待期间模型变化、HTTP 流式检查、端点变化、活跃音色判断和共享流式服务。
排队复用用例通过事件屏障覆盖普通/文件合成先完成、不同台词、关闭缓存和中途取消，
核对引擎调用次数、缓存写入次数和命中统计，不以机器负载下的毫秒阈值代替行为验证。
原有缓存命中基准仍要求只调用一次合成器；预期键现在带入有效客户端参考参数。

`tests/test_tts_voice_preparation.py` 覆盖首句准备、三种入口、资源不足、文件或地址变化、
不能伪造的解析标记、缓存复用、与手动切换互斥、取消恢复和加载失败后的重试。

缓存读取、真实原地截断、版本替换竞态和 Windows 文件占用的回归见
`tests/test_tts_cache_io_budget.py`；测试使用真实临时文件和数据库并注入读取/替换错误。
